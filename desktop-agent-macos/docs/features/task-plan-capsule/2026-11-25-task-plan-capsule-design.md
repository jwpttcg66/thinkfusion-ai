# 任务规划胶囊（输入框正上方）设计

日期：2026-11-25  
状态：已实现；真机 CDP 验收通过（2026-11-25）  
方案：**A · dock 胶囊**（已确认）

## 目标

只允许**输入框正上方**变化。滚动正文只保留已落盘内容；实时任务规划状态与正文定位轴挂在 dock，和正文分开。

## 布局

```
┌──────────── scroll（正文，只追加落盘内容）────────────┐
│  已完成的消息 / 卡片 / 结论 …                         │
│  （不再插入 routing 心跳、Progress 条、思考中条）      │
└──────────────────────────────────────────────────────┘
┌──────────── dock（不随正文滚动）──────────────────────┐
│         ┌──── 任务规划胶囊（居中，与输入同宽上限）──┐ │
│  用户消息│  上：任务计划目标                         │ │
│  短杠定位│  下：圆环 + 当前步骤一句 + n/m            │ │
│  (历史话)└──────────────────────────────────────────┘ │
│         ┌──── TaskInput ───────────────────────────┐ │
│         │  问点什么…                                │ │
│         └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

- 挂在 `.dock` 内、`TaskInput` **正上方**，`max-width` 与 `.inner` / 输入框一致并居中。
- **不进** `.scroll`，避免滚动时挤动正文。

## 胶囊内容

### 上半：任务计划目标（不是用户原话）

优先级：

1. `conversation.goal.text`（有则用）
2. 否则 workbench / plan 的目标或计划标题
3. 再否则占位：`正在理解任务目标…`

明确禁止：把本轮用户原话塞进上半。

### 下半：当前步骤

- 左侧圆环进度（进行中动画；终态静止）
- 中间一句：当前阶段说明（复用 `deriveProgress` 的 `current.label` + `detail`）
- 右侧 `n/m`：当前活动阶段序号 / 总阶段数（来自 `PROGRESS_STAGES` 投影，不是随意写死）

数据源：现有 `deriveProgress` + `events`，不新造第二份进度状态。

## 用户消息定位轴（一列细横杠）

**语义：只定位「玩家以前发给这个任务的信息」，不是阶段进度，也不是计划/汇总/结论等地标。**

- 胶囊**左侧**一列细横杠，视觉参考 Cursor 式短杠：默认灰，**当前正在看的那条用户消息**加亮。
- **每一杠 = 正文里一条历史用户消息**（本任务/会话里用户曾经发出去的 prompt）。系统卡、模型回答、判定/汇总块**不占杠**。
- 点击 → 滚动 `.scroll` 滚到该条用户消息锚点。
- 当前高亮跟正文滚动位置同步（哪条用户消息在视口里），**不跟** `n/m` 绑死。
- `n/m` / 圆环 = 任务阶段进度；短杠 = 「跳到以前某次发给任务的话」——两者并存、职责不混。

实现时：给每条用户消息挂稳定锚点（如 `data-user-msg` / message id）；短杠列表只从 messages 里 `role=user`（或等价）投影。无历史用户消息时不显示空轴。

## 正文清理（只允许下方变）

从对话流中移除或停用以下「中间插卡」：

- `conv-live-bottom`（工程判定实时卡 + 「思考中」条）——连通/思考改由胶囊下半表达；落盘后的正式「工程判定」卡仍可出现在正文（作为已完成内容）。
- 挂在对话流之后、仍随 scroll 区域一起跳的 `ProgressPanel`——迁入 dock 胶囊下半，不再单独占一行挤正文。

终态：胶囊可收成紧凑「已完成 / 已失败」一行，或短延迟后隐藏；**不要**整段 `return null` 导致 dock 高度猛跳（与现 ProgressPanel 终态策略一致：保留壳或固定占位）。

## 显示条件

显示当且仅当：

- 当前是会话 chat 页，且
- 会话/任务非空闲进行中（thinking / collecting / synthesizing / planning / executing / verifying 等），或刚结束保留终态壳；
- `debateOnly` 等不适用五段进度的模式：胶囊可只显示目标 + 简化步骤，定位轴仍按正文地标。

空首页（无会话）不显示胶囊。

## 验收

1. 发送云端/工程任务后：胶囊出现在输入框正上方居中；正文顶部不出现跳动进度条。
2. 上半是目标文案，不是用户原话。
3. 下半随阶段更新 `步骤文案` 与 `n/m`；中上部已落盘块位置不变。
4. 左侧细横杠每条对应一条历史用户消息，可点跳到该条；滚动正文时当前用户消息对应杠加亮。
5. 任务结束后 dock 高度不猛跳。

## 非目标

- 不重做整个对话流卡片体系。
- 不把短杠做成计划/汇总/结论地标轴（那是另一套；本需求只要用户历史消息）。
- 不把定位轴改成带长标签的侧栏（工程页现有宽轨可保留；本胶囊侧用细杠）。
- 不在本轮改主进程判定协议；只消费已有 goal / events / messages。
