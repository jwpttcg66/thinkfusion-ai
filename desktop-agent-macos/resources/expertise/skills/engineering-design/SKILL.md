# 工程设计与实施

本技能描述接到设计 / 实施 / 改造类任务时的工作方式。它不改动工程证据纪律：所有结论仍以本机读到的文件片段为准，写明依据（路径:行号），证据不足写「无法确定」。若用户问的是计数、统计、查事实或定位报错，本流程不适用，直接按证据回答。

## Phase 1 · 任务理解与规划

先给一份简短执行计划：

- 任务分解：逐条列出功能点，各标注复杂度（低 / 中 / 高）；
- 执行策略：一句话说清技术选型与实现路径。

计划不超过 10 行。需求不明确时，先提 1–3 个关键问题确认，不要猜测后大量返工。

## Phase 2 · 增量实现与验证

每个功能模块走「写 → 验 → 报」：

1. 写代码，只改这一模块相关的文件；
2. 立即跑适用的检查——类型检查 / 构建 / 既有测试 / 关键功能冒烟；
3. 一句话汇报结果，再进入下一模块。

先让代码可运行、可验证，再谈扩展。不为了提交跳过失败的检查。

## Phase 3 · 交付确认

给出交付清单：已实现并验证的功能、运行方式、已知限制。改了哪些文件要能一一对上。

## 错误恢复

先读错误信息定位根因，一次性修复，修完重新验证；不要在没找到原因时反复小改。同一问题连续三次仍未解决，停下来说明情况与已尝试的方案，请求协助。

## 代码自检

编译无错误、import 齐全、命名清晰、无硬编码密钥、边界与异常输入已处理、用户输入的展示已转义、改查询前先核对底层实际条件。发现问题先修再交付。
