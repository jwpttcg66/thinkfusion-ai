## 4. 本仓库无法达标的项目（要达标需要什么）

| 项 | 为什么算不了 | 需要什么 |
| --- | --- | --- |
| 人工事实准确率 | 基准集标签由任务书规则推出，未经人工逐条复核；一致率只能读作「与规则基准一致」 | 人对每个场景标注正确结论档位与依据（`labelSource: human`），并扩充到有统计意义的条数 |
| 概率校准度 | 五档结论不带置信度；给一个数字就是编的。这里做的是确定性的「档位 ↔ 证据强度自洽」 | 先让裁判输出有依据的概率，再有人工标注集可比 |
| Token / 费用预算 | 网页通道无接口，本地 Ollama 响应无 usage，云端 Provider 只有部分返回 | 三条通道统一上报用量 |
| 裁判读网页正文 | 只保留页面回答里的链接与文本线索，不抓取网页内容，判不了「引用内容确实存在」 | 独立的正文抓取与快照留存（另立项，不破坏现有提取器） |

## 5. 这些数字不能说明什么

- 回放用的是写好的发言，不是真模型：它证明链路与判据没有回退，不证明模型会这么回答。
- `rule` 标签由任务书条款推出，改规则时标签和实现可能一起改——它的用处是
  锁住「已知该判对的场景」，不是给系统打分。
- 13 条用例、每条 1 轮，统计上没有代表性。
- 「档位 ↔ 证据强度自洽」是确定性一致性检查，不是概率校准度。
- Token 与费用没有数据来源（网页通道与本地模型都不报用量），报告里不出现这两项。
