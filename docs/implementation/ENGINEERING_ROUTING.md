# 工程路由改由模型判定

日期 2026-11-09。用户裁决原话：「这个动作是不是可以用模型来决定怎么做呢，程序猜测这个可能已经不合适了」，
随后补「模型的时候模型判定，混合模式模型自己判断」「本地最小模型优先，云端兜底」。

## 1. 原来的问题

`shared/workspace.ts` 用两张动词表判「这句话是分析还是实施」：

- `EXECUTION_VERBS` 已经 400 多个字符，`ANALYSIS_VERBS` 130 个；
- 每踩一个说法就补一个词，仍然漏：真机上「这个方案」+ 一份 `.md` 就被判成
  「待确认」，文件读了、却什么都没发生；
- 用户没法知道哪句话会被判成待确认，只能事后被拦一次。

枚举对抗自然语言，必然是越补越漏。这类判断本来就是模型擅长的。

## 2. 现在的判定流程

工程空间里，**模型主导（本地 / 云端 / 混合）时由模型判**；网页主导按规则。
四道闸门按顺序，任一命中就停：

| 顺序 | 条件 | 结果 | 为什么 |
| --- | --- | --- | --- |
| 1 | 用户选了「本次按分析 / 本次按实施」 | 直接采用，不问模型 | 用户明确指令优先 |
| 2 | 还没选工程目录 | 规则结论（先让用户选目录） | 判了也跑不了 |
| 3 | 网页主导 / 没接线 | 规则结论 | 网页读不到别人的回答，分类问题还会在用户账号里留一条无意义会话 |
| 4 | 模型超时 / 报错 / 回的不是 JSON | 规则结论 | 判定失败不许拦提问 |

模型正常返回时，用它的结论覆盖规则；`source` 记成 `model`，理由写成
`模型判定：<模型给的那句话>`，界面上看得见这次是谁判的。

## 3. 用哪个模型

`main/index.ts` 的 `routeEngineeringWithModel()`：

1. **本地默认模型**（`localProvider`，即设置里的默认本地模型）先试；
2. 失败再遍历**已配置 Key 的云端服务**，用各自的第一个模型；
3. 都失败返回 `null`。

不碰网页通道。整个调用有 4 秒上限（`ROUTING_TIMEOUT_MS`），用一个 system 段
+ 一行 JSON 的输出格式，输出长度约 30 token。

## 4. 边界（这些都还没变）

- **只判路由，不干活。** 分类调用不读文件、不执行、不接触网页。
- **用户原话逐字进模型。** 问句是 `用户的这句话：<原文>`，附件只报名字不塞正文，
  不套角色话术（老规定：固定提示词不进提问链路）。
- **识别 ≠ 授权。** 模型判成「实施」只是进执行计划，写文件仍要过沙箱与逐次审批。
- **知识空间零改动。** 这条链路只在 `workspaceMode === 'engineering'` 时进入。
- **规则没删。** 它从「主判」降为「兜底」与「网页主导时的唯一判据」。

## 5. 输入框上那个标签

模型主导时，输入框里那份只是**规则预估**，真正判定在发送时。所以标签改成
「发送后由模型判定这一句是分析还是实施」，不再写死「本次判为『工程分析』」——
否则面板和实际行为会各说一套。用户指定过「按分析 / 按实施」时照旧显示「（你指定的）」。

## 6. 测试

```
npm run test:routing-model   # 10 条：问句、解析、套回、四道闸门
npm run test:workspace       # 规则本身（现在只做兜底）没退化
```

`check-routing-model.mjs` 覆盖：

- 问句里用户原话逐字在、附件只报名字、system 不含角色话术；
- 解析能吃裸 JSON / 代码块 / 中文 kind / 大小写；`{}`、无 kind、非 JSON 一律 `null`
  （**绝不把「认不出」当成「分析」**）；
- 套回时只改判定与理由，规则算出的 `needsProject` 保留；
- 本地 / 云端 / 混合三档真的调用模型；网页主导一次都不调；模型返回 `null` 或抛错
  退回规则；用户指定与「没选目录」都不调模型。

## 7. 已知代价

1. **每个工程提问多一次小调用**（本地约 0.3–1.5 秒，云端再加网络）。这是「让模型判」
   的必然成本；网页主导没有这份开销。
2. **本地只有一个推理槽**（`LocalAdmission`，24GB 统一内存）：判定会短暂占用它，
   紧接着的真实回答排队等一小会儿。4 秒上限保证不会长时间占着。
3. **判定不再可复现**：同一句话两次可能给出不同结论。所以保留了用户 override 与
   `reason` 展示，用户能看见判据并当场改判。
4. **模型可能判错**：错误方向被限制在「只读 / 实施」之间，越权由审批拦住，
   不会因为判错就静默改文件。
