# UI 改造计划

状态：**延后**。P1 不做产品 UI 改版（只写事件日志）；本文作为 P3/P4 之后的实施计划。

目标：用户只说目标；界面解释「在做什么、谁在做、凭什么、为什么停」。
原则：不新增页面框架，先复用现有三栏与进度区；所有内容来自 P0 事件。

---

## 1. 要删除的用户入口

| 入口 | 处置 | 兼容 |
| --- | --- | --- |
| 辩论模式 / 策略选择 | 从主界面移除 | 旧会话字段只读，不再写新值 |
| 真理发现 / 对抗 / 专家 / 方案竞争 | 移除 | 无 |
| 「Round 1/2/3」过程展示 | 改为任务视图 | 历史记录仍可回看 |

调试用途可在设置页保留一个隐藏开关（开发模式），不面向普通用户。

---

## 2. 主界面结构（复用现有）

```text
左栏：目标与计划
  ├─ 目标（用户原话）
  ├─ 工作空间
  ├─ 计划摘要：N 个任务 / 参与者 / 预计步骤
  └─ 停止原因（结束后）

中栏：对话与交付
  ├─ 回答 / 报告 / 知识地图 / 改动
  ├─ 关键结论（可展开证据）
  └─ 未核验与缺口

右栏：协作与证据
  ├─ 参与者：状态、失败原因、是否被跳过
  ├─ 任务：等待 / 进行 / 完成 / 失败
  ├─ 证据：来源、版本、哈希、是否可复验
  └─ 重规划：为什么加了/删了任务
```

---

## 3. 事件到界面的映射

| 事件 | 界面 |
| --- | --- |
| `goal.started` | 左栏目标与空间 |
| `plan.created` | 计划摘要（任务数、参与者、理由） |
| `task.started` | 任务行进入「进行」，显示 agent 与理由 |
| `observation.recorded` | 任务完成/失败/跳过；失败显示原因 |
| `plan.revised` | 出现一条「计划调整」并写明原因 |
| `goal.stopped` | 显示停止原因与时间 |
| `deliverable.ready` | 中栏交付物；证据可展开 |

不新造状态：界面只投影事件，不自己推导「应该到哪一步」。

---

## 4. 关键视图

### 4.1 结论与证据

- 每条结论旁：`已验证 / 有争议 / 未核验 / 断言` 四态；
- 点击展开：依据 → 来源（网页/代码行/执行断言）→ 时间/版本；
- 没有证据的结论不能伪装成「已验证」。

### 4.2 参与者

- 显示所有已开启通道，包括被跳过的；
- 跳过/失败必须给出原因（未登录、不可用、超时、能力不匹配）；
- 不允许只显示成功者。

### 4.3 工程任务

- 文件清单、`路径:行号`、影响面；
- 计划 / 审批 / worktree / 测试 / diff / 回退入口；
- 「已通过」必须能点开到 attestation。

### 4.4 知识学习

- 知识卡：结论、条件、时效、状态；
- 知识地图三块：已确认 / 有争议 / 未回答；
- 复用旧结论时显示「依据时间 / 版本」。

## 5. 分阶段落地

| 阶段 | UI 范围 | 验收 |
| --- | --- | --- |
| P1 | **不做**；仅内部日志与调试只读 | 日志能解释为什么停 |
| P2 | 知识卡、地图、时效标记 | 第二次研究能看到旧结论与过期提示 |
| P3 | 工程任务视图、审批、diff、测试、回退 | 一次真实改动全程可见 |
| P4 | 证据展开、验证状态、指标（可选调试） | 任一结论能点到证据 |

---

## 6. 可用性与边界

- 长任务必须有进度，不允许「转圈到结束」；
- 失败不是空白：显示失败任务与下一步；
- 不显示内部 Prompt、不显示模型思维过程；
- 不把「辩论轮次」重新包装成「任务阶段」展示；
- 键盘可达、对比度符合现有设计规范。
