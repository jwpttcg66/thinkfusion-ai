## 1. 裁决

用户原话：「工程模式模型为第一意见，网页是辅导重大决策用的第二意见」。

这是上一轮裁决的下一句。上一轮（同日）定的是「工程模式，不需要优先问网页，读取本地
应该是模型所做的」——工程空间的第一手回答从网页搬到模型。这一轮把网页放回来，但换了
位置：它不再回答事实，只在**决策**上复核。

两句话合起来是工程空间现在的分工：

| 角色 | 谁 | 依据什么 | 什么时候 |
| --- | --- | --- | --- |
| 第一意见 | 本地模型（云端主导时才用云端） | 程序真实读盘得到的工程证据 | 每个工程问题 |
| 第二意见 | 一个网页通道 | 用户原话 + 第一意见 + 证据摘录 | 只有决策类问题 |

知识空间完全不受影响：那里仍按 2026-11-05 的硬规则，原话直发所有已开启网页通道。

## 2. 为什么网页只能当第二意见

因为网页读不到本机文件。把「这个文件多少条记录」发给它，它只能回「请上传」——
真机 s20/s21 连着两轮都是这个结果。所以：

- 第一意见只能由能拿到证据的一方给（模型）；
- 网页能给的，是**另一个判断**：它看不到文件，但看得到我们递过去的证据摘录与第一意见，
  能指出「这个改法三个月后会痛」「这个依赖明年停止维护」这类证据本身不会说的话。

这也解释了为什么材料里必须带第一意见：没有靶子，网页给的只是「另一份并列的看法」，
用户拿到的不是复核，是两份互不相干的作文。

## 3. 什么算「重大决策」

判定是**规则**，不是模型（`classifyDecision`）。交给模型要多一次生成，而且判错时被
静默放过的那条，恰恰是本该复核的决策。

- **强信号（单独命中即算）**：要不要、该不该、是否应该、值不值得、建议、推荐、选哪个、
  迁移、重构、升级、替换、回滚、上线、发布、部署、删除、移除、废弃、风险……
- **弱信号（两处命中，或一处 + 疑问语气）**：比较、对比、取舍、权衡、选型、替代方案、
  优缺点、性能、安全、成本、依赖、接口、数据库、表结构、兼容、并发、内存、缓存、协议、规范、方案
- **用户点名**：「问问网页」「第二意见」等，跳过判定直接问。

事实查询（读取、统计、多少条、报错在哪一行、这个函数干什么）不命中，所以不发网页：
它们看不到文件，问了只会把摘录复述一遍，白等两分钟。

## 4. 行为边界

- **只问一个通道**：取勾选范围内第一个可用的。每个网页都要重新加载、键入一整段、
  等它写完，两分钟起步；多问一家只是把这段等待翻倍，不会让决策更清楚。
- **证据摘录上限 6000 字**：整段工程材料可达数万字，页面读完反而答得更散；超限时
  明确写「以上是摘录：证据共 N 字，只发了前 6000 字」，不假装是全文。
- **两份意见并列，不做汇总**：追加了第二意见就跳过执行阶段，也不跑规则版融合。
  规则版是按文本相似度拼的，判断「两条意见算一致还是分歧」靠词面重合，对
  「该不该迁移」这种问题只会给出一个看着像结论、其实是统计的段落。
- **问不问都要说**：问了写「网页第二意见：ChatGPT（问题在问「要不要、迁移」，是要
  拍板的决定）」；没问写「不需要网页复核：这不是决策类问题（读数、查事实、定位错误）」。
  用户不该从沉默里猜网页为什么出现或为什么没出现。
- **失败不假装**：网页超时/卡住就记一条失败（`JSON：页面卡住了`），第一意见仍在，
  这一轮仍是 answered。
- **预算顺延 3 分钟**：网页侧要走「加载 → 键入 → 等它写完」。被外层预算砍掉的第二意见
  比不问更糟——用户等了几分钟，拿到的是「超时」。

## 5. 三档设置

研究设置 → 执行模式 → 「工程空间：网页第二意见」：

| 档 | 行为 |
| --- | --- |
| `auto`（缺省） | 只在判定为决策类问题时问 |
| `always` | 每个工程问题都问一次 |
| `off` | 只留模型的第一意见 |

缺省 `auto` 是这次裁决的落点，不是历史行为：升级前工程空间完全不问网页，因为那时
「第一手回答永远发网页」照搬到工程空间只会得到「请上传」。既然网页现在有明确职责
（复核决策），它就该在决策上出现，不必等用户手动开一次。
