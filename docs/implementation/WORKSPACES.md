# 工作区（多项目侧栏分组）

日期 2026-11-09，分支 `0.1.4`。此前侧栏只有「知识学习 / 工程工作」两个 space，会话在 space
里平铺；同时做两个工程时，历史没有任何分组依据。现在工作区是独立的一层：
一个名字 + 一个本地目录，会话归到工作区下，侧栏按工作区折叠显示。

## 1. 原来缺什么

| 缺的东西 | 表现 |
| --- | --- |
| 会话没有归属 | 所有会话按时间排一列；切换到另一个项目，上一项目的历史混在一起 |
| 项目只是一次性参数 | `workspaceRoot` 是全局一个路径，选新目录就覆盖旧的，没有「有哪些项目」 |
| 没有分组管理 | 想收起某个项目的记录，只能删；删了历史就没了 |
| 升级兼容 | 老会话只有 `workspaceRoot`，没有工作区 id，需要能按目录归位 |

## 2. 数据模型

### 工作区清单

`userData/workspaces.json`，由 `main/workspace-list-store.ts` 读写，形状是
`WorkspaceEntry[]`：

```ts
interface WorkspaceEntry {
  workspaceId: string; // 随机 id，不跟目录走
  name: string;        // 用户可改；默认取目录末段
  root: string;        // 绝对路径，末尾斜杠归一
  createdAt: number;
  updatedAt: number;
}
```

约定：

- 同一个目录只留一条（按去掉末尾斜杠后的路径比较）；
- 坏条目跳过，不影响其他工作区；
- 名字可以为空读成目录末段，但重命名时拒绝空名字；
- 移除工作区只删分组，**不删目录、不删会话**。

### 当前工作区

`userData/workspace-state.json` 的 `WorkspaceState` 增加
`activeWorkspaceId`。它和 `workspaceRoot` 分开：

- `activeWorkspaceId` 决定「下一问归到哪一组」；
- `workspaceRoot` 决定「工程分析读哪个目录」。

知识会话也会挂在工作区下，但它不读目录，所以两个字段不能合并。

### 会话归属

`Conversation.workspaceId?`。老会话没有这个字段，侧栏按以下顺序回退：

1. `workspaceId` 命中工作区 → 归到该组；
2. 没命中时用 `workspaceRoot` 找同目录的工作区 → 归到该组；
3. 都找不到 → 「未分组」。

第 2 条是升级兼容的关键：不需要改一次盘，老会话也能回到原来的项目下。
工作区被移除时，`AgentStore.clearConversationWorkspace()` 一次性清掉这些会话
的 `workspaceId`，它们会出现在「未分组」里，历史一条不少。

## 3. IPC

| 通道 | 作用 |
| --- | --- |
| `workspace:list` | 工作区清单 |
| `workspace:add` | 加目录（已存在则返回原条目），并切换为当前工作区 |
| `workspace:rename` | 改名；空名字被拒绝 |
| `workspace:remove` | 删除分组，返回 `clearedConversations`（移到未分组的条数） |
| `workspace:get/set` | 原有的空间/项目状态，`set` 现在也接受 `activeWorkspaceId`，指向不存在的组会报错 |

`conversation:submit` 新增 `workspaceId`，只接受真实存在的组；不存在时忽略，
会话落到「未分组」，不静默挂到别的组下。

## 4. 侧栏

- 顶部只有品牌标识，不再有「更多」菜单：这三个入口都另有位置，菜单只是重复；
- 「工作区」标题栏：会话搜索、全部展开/收起、添加工作区；
- 侧栏底部账号行：页面诊断、设置；
- 每个工作区一行：折叠箭头、目录图标、名字、会话数、`⋯`（重命名 / 移除）；
- 会话行：状态点、标题、相对时间；悬停时删除；
- 字号与行距按参考图放大：工作区名与会话标题 14px、时间 12px、分组标题
  13.5px，单行约 34px；会话标题与工作区名字左对齐（点挂在左侧），不再往
  左缩进；
- 搜索只过滤标题，空工作区在搜索时隐藏；
- 「未分组」只在有内容时出现，固定排在最后。

「知识学习 / 工程工作」两个 tab 仍然保留，只做筛选：切换 tab 不删历史，也不
改变任何会话的归属。原 V2.1 的验收口径不变。

## 5. 安全边界

工作区**不是授权**。它只决定分组和新会话默认项目；读写文件仍然走计划、
`TaskGrant`、路径校验和逐次审批。添加一个目录不等于允许模型动它。

## 6. 迁移

启动时如果 `workspaces.json` 为空、而 `workspace-state.json` 里已有一个
`workspaceRoot`，自动把它建成第一个工作区并设为当前；只在列表为空时做一次。
如果当前 id 指向已不存在的工作区，清空它，避免侧栏显示「当前」却找不到。

## 7. 测试

`npm run test:workspace` 共 19 条，其中新增 7 条：

- 纯函数 4 条：工作区列表（坏条目跳过、同目录去重、名字取目录末段）、
  侧栏分组（先按 id，老会话按目录，最后落未分组）、空工作区也列出、
  工作区被移除后会话落到未分组；
- 落盘 3 条：加目录真的写进文件、同目录重复添加只返回原条目、重启读回
  id 与名字不变；改名拒绝空名字且失败不留半个新名字；移除后文件同步清空；
  坏 JSON 退回空列表且不删用户的文件。

面板交互在浏览器预览（`VITE_MOCK=1`，无 Electron）里逐条点过：分组与计数、
当前组高亮、单组折叠、`⇅` 全部收起/展开、`⌕` 搜索时隐藏空工作区、点击工作区
行切换并收起、`⋯` 改名（空名字就地报错）、移除后会话落进「未分组」且提示条数。
真机 Electron 的添加目录对话框、重启读回尚未做，不写进验收报告。
