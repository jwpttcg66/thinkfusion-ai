# P6 多轮自主研究

> 背景：ROADMAP 里最后两项没做的能力之一。V2.1 之前，一次提问 = 一轮多通道回答 +
> （可选）辩论，问完就结束；主导人自己都会在【存疑】里写下「缺一个具体数字」，
> 而这条线索到此为止——用户要自己再打一遍追问。
>
> 这一轮把它接上：**让主导人指出缺口，把缺口重新问一遍所有网页通道，再更新汇总**。
> 默认关闭，轮数上限 3，每一轮的发生与停止都写在会话里。

## 1. 为什么不是「自动多问几轮」

任务书与用户裁决里有两条硬约束，直接决定了这个功能的形状：

1. **Auto 不得无声扩大调用与成本**。自动续问正是最容易失控的那类自动化：每多一轮
   就是「所有网页通道各多回答一次 + 主导人多写一次汇总」，而用户看到只是等待条
   转得更久。所以它是显式开关（研究设置 → 研究轮次），默认 0 轮，选了才发生。
2. **提问原样发出，不套角色行**。追加研究发出去的也必须是一句正常人会问的话，
   不能是「你是我的研究伙伴，请围绕以下缺口……」。页面会把我们发的东西回显进
   转录，套话越长越剥不干净。

另外一条来自归属规则：追加研究**只重问网页通道**——第一手回答永远来自网页。

> **2026-11-08 附记：** 工程空间的第一手回答已改由模型读证据给出（见
> `ENGINEERING_MODEL_FIRST.md`）。那里只有一份回答，执行阶段本来就跳过，所以
> 追加研究在工程空间不会发生——也不会再把缺口丢回网页。
主导人仍按归属规则（网页 / 本地 / 云端 / 混合择一）执行汇总，不在这一轮引入新的
成员类型。

## 2. 一轮追加研究做了什么

```
第一轮：用户原话 → 所有网页通道
        → 主导人汇总【结论/一致/分歧/存疑/辩题】+（开了追加研究时）【待补】
        → 辩论（可选）
        ↓
追加轮（最多 followUpRounds 轮）：
  1. parseFollowUps    从【待补】取出具体缺口（最多 3 条）
  2. decideFollowUp    还问不问（停手 / 跑满 / 无缺口 / 已问过）
  3. buildFollowUpQuestion  拼成一条普通问题
  4. 所有网页通道重新回答（continuing：不重置，接着上一轮说）
  5. 主导人把新回答并进汇总，重写同一套五段
  6. 更新后的汇总成为这一轮的结论；下一轮再从它的【待补】继续
```

停止条件按优先级：用户停手 > 单轮设置 > 跑满上限 > 主导人没给缺口 > 缺口上一轮
已经问过。**每一个停止都写一条系统消息**说明原因，包括「没有可补的问题」这种
看起来什么都没发生的情况——沉默是最难排查的状态。

## 3. 边界（刻意的）

| 不做 | 为什么 |
| --- | --- |
| 程序自己猜缺口 | 那等于替用户定研究方向，还把成本算在他头上。缺口只能来自主导人的【待补】 |
| 追加轮里重开辩论 | 辩论已在第一轮跑过；为一个补回来的数字再辩一场是成本翻倍、结论不变。需要辩的分歧第一轮就会列出来 |
| 追加轮引入本地/云端模型 | 归属规则；第一手回答永远来自网页通道 |
| 把上一版汇总当成「补充后」的汇总 | 更新失败就停在上一版，并写明是谁没给出更新 |
| 无限续问 / 自适应轮数 | 上限 3，界面可选 0/1/2/3；轮数是用户选的，不是程序决定的 |

超时预算也跟着走：`run()` 的等待上限 = 5 分钟 + 每轮 3 分钟。原来固定 5 分钟，
开了深挖反而会被外层预算砍掉，拿到的比单轮还少。

## 4. 实现位置

| 文件 | 内容 |
| --- | --- |
| `src/shared/conversation.ts` | `ConversationExecutionConfig.followUpRounds`（缺省 0）、`MAX_FOLLOW_UP_ROUNDS = 3`、归一化时夹到 0–3 |
| `src/main/research/follow-up.ts` | `parseFollowUps` / `decideFollowUp` / `buildFollowUpQuestion` / `buildFollowUpSummaryQuestion` / `followUpNote` / `followUpBudget` |
| `src/main/synthesis/lead-stage.ts` | `LEAD_FOLLOWUP_SECTION`（【待补】那段要求）；`leadSummarySystem(taskKind, followUp)` 与两个 question 构造器多一个 `followUp` 开关，**默认关闭时提示词与以前逐字相同** |
| `src/main/conversation-runner.ts` | `deepenResearch()`：追加轮主循环；`conduct()` 在写综合之前调用它；`setStatus()` 在用户停手后不再改状态 |
| `src/renderer/src/components/ResearchPanel.tsx` | 「研究轮次」下拉，写明每多一轮的成本 |

顺带修掉一个真问题：`cancel()` 把状态改成「已停止」后，还在飞的那一轮仍会按自己
的节奏写「收集中」，界面上表现为「点了停止，卡片又转起来」。`setStatus()` 现在
在用户停手后拒绝一切非停止的状态更新。

## 5. 测试

`scripts/check-followup.mjs`（20 条，已挂进 `npm test`）：

- 纯函数 13 条：【待补】解析（编号挤一行、多条上限 3）、「无/没有/无需补充」、
  站点追问「需要我继续查吗」不被当缺口、markdown 强调/行内代码被剥掉、单条过长截断、
  预算夹取（含字符串 `'2'`）、五条停止条件、发出去的问题不带角色话术、第二轮措辞、
  更新汇总问句、**不开追加研究时提示词一个字都不变**；
- 链路 7 条：默认单轮不追加也不要求【待补】、开一轮后缺口被问回**所有**网页通道
  且结论换成第二版、缺口重复就停并说明、没有【待补】就停并说明、追加通道全失败
  时结论停在上一版、掉登录通道的失败只记一次、用户停手后不再追加。

全量：45 个子脚本 / 672 条 `test()` 用例 + 27 条协议检查，`typecheck` / `build` 通过。
