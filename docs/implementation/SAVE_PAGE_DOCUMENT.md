# 网页源「保存文档」

2026-11-08 实现。需求：「网页源顶部增加保存文档功能，每个网页源可以提取网页的里面的文档和计划，保存到本地文档里面」。

## 放在哪儿、作用于哪个源

按钮在网页栏（`.page-bar`）的动作组：两个图标按钮——「保存文档」（纸 + 下箭头，默认
Markdown）和「保存为 Word」（同一张纸，里面是横线）。网页栏是 DOM，页面本身是
native view，画在页面上的按钮看不见，所以只能放这一条栏里。

2026-11-09 补：网页源「放大」成独立窗口后，主窗口那条页面栏不再对着眼前的页面，
独立窗口自己的工具栏原先只有「吸附回去」，保存入口就丢了。独立窗口工具栏现在
带上同一组「保存文档 / Word」图标，路径数据与主窗口共用 `shared/icons.ts`。
独立窗口挂一份只暴露保存的 preload（`src/preload/detached.ts`），点按钮走
`page:save-from-detached` → 同一个 `page.save-document` 插件。早先试过改
`location.hash` 让主进程听 `did-navigate-in-page`，在 `data:` 页上经常不触发，
按钮在却点了没反应——所以换成正式 IPC。

动作接受 `sourceId`：界面传当前显示的那个源，调用方也可以指定别的源，只要它的页面
view 已经创建过。「网页源没打开 / 还在加载 / 停在登录页或空会话」都明确报错，不写空文件。

## 提取什么

**文档**＝页面里每条助手回答的原文。复用提问链路的 `PROBE_SCRIPT`，加了一个默认关闭的
`allAnswers` 开关：打开时把每个回答气泡都用同一套 `structuredText` 读成 Markdown（标题、
列表、表格、代码块、粗体），而不只是最后一条。默认关闭是硬要求——轮询每几秒探测一次，
把几十个气泡逐个结构化遍历会把页面读成卡顿。

**计划**＝从这些原文里挑出的步骤条目，是同一份文字的索引视图，不是新写出来的计划：

- 只有先看到带「计划 / 步骤 / 待办 / checklist / roadmap…」字样的标题，或带 `- [ ]`
  复选框的行，才把后面连续的列表行收进来；
- 普通文档里的项目符号不会被算成待办（真机里一份说明书能凭空多出几十条「计划」）；
- 完全相同的条目只留一条（同一页常把一问重发一轮，计划块整段重复）；
- 一条都没认出来就写「没有识别到计划类条目」，不硬凑。

全程不经过模型、不改写一个字、不做第二次总结。

## 成稿结构

```
# 页面标题
> 由 ThinkFusion 从「<网页源>」网页提取于 …；下面的文档与计划是页面原文，未经改写或总结
## 提取概览        （网页源 / 页面标题 / 地址 / 文档数·字数 / 计划条目数，单元格转义竖线）
## 文档            ### 文档 1…N，逐条原文
## 计划            （挑出的条目，照原样带 - / - [ ] / 1. 标记，不再套一层短横）
## 附录　页面转录（节选）   （默认附，节选 6000 字并注明剩余；includeTranscript:false 可关）
```

格式沿用会话导出的裁决：**默认 md，只有明确写 `doc` / `docx` / `word` 才生成 Word**；
docx 模块按需动态加载。文件名取页面标题清洗后加时间戳，保存位置默认弹系统对话框
（起始目录「下载」），`path` 直写留给自动化与真机验收。

## 保存前先勾选（0.1.8，2026-11-11）

一页里往往不止一条助手回答；以前点保存只能整页存下来。现在按微信多选的做法：

```
点「保存文档」/「保存为 Word」
  → page:extract：只读预览，列出这一页能保存的对话（标题 / 前 160 字 / 字数）
  → 多选面板（PageSaveDialog.tsx），照微信多选的样子：
       左边圆点勾选；提问靠右（绿色气泡、头像「我」），回答靠左（白色气泡、站点首字）
       每条上方标「第 N 条 · 我问的 / 回答 · X 字」，一眼分得出问和答
       底部动作条：逐条保存（N 个文件）/ 合并保存（1 个文件 · N 条）/
                   全部保存（全部 N 条）/ 取消
       合并保存：勾选的写在同一个文件里（默认 Markdown / Word 按入口）
       逐条保存：勾选的每条各存一个文件，放同一个文件夹；不附页面转录
       全部保存：不挑，整页存一份（等同于旧行为）
```

边界：

- 面板只回传下标（`documents: number[]`），正文仍由主进程在保存时现读页面；
  列表和落盘内容不会来自两个时刻。
- 越界或已被页面清掉的下标会被忽略；一条都不剩就明确报「没有可保存的对话」，
  不写空文件。
- 代码块（`<pre>`）原样保留：结构化提取的收尾会削掉每行首尾空白，而代码/ASCII
  图的缩进是内容。先用不含空白的占位符替换代码块，收尾后再换成三反引号原文。
  真机上一张架构图曾因此被削成左对齐，保存下来和页面不是一张图。
- 勾选下标指向「问答记录」：页面探针在 `allAnswers` 模式下额外读提问气泡
  （`ProviderProfile.user`，站点没给就只列回答），按 DOM 顺序排成
  `allMessages`。保存成稿时用 `## 对话` + `### 问 N / 答 N`；只有回答的旧内容
  仍是 `## 文档` + `### 文档 N`。计划条目只从回答里挑，提问不会变成待办。
- `per-item` 的 `path` 是目录；结果里带 `files` 清单，界面说「存了 N 个文件」。
- 独立窗口工具栏的保存仍是一次存全部：那条链路没有多选面板。

## 链路

```
page-bar 按钮（App.tsx）
  → window.agentAPI.extractPage({ sourceId })       ipcMain 'page:extract'（只读预览）
  → 多选面板 → window.agentAPI.savePageDocument({ sourceId, format?, documents?, mode? })
  → ipcMain 'page:save-document'                    src/main/index.ts
      ├─ PROBE_SCRIPT(profile, …, allAnswers=true)  src/main/adapters/browser/page-driver.ts
      └─ savePageDocument()                        src/main/export/page.ts
           ├─ buildPageDocument()                  src/main/export/page-document.ts
           └─ writeFileAtomic / markdownToDocx（仅 docx）
  → { path, format, bytes, documents, planItems, chars }（null = 用户取消）

独立窗口工具栏（detachedDocument + preload/detached.ts）
  → window.tfDetached.saveDocument('md' | 'docx')
  → ipcMain 'page:save-from-detached' → pageDocumentSaver(...)  同上一条插件
```

## 测试与真机

- `npm run test:page-document`（scripts/check-page-document.mjs，20 条）：计划块边界、
  复选框、去重、原文照搬、表格转义、转录截断与开关、空页面、默认 md / 点名 doc、
  取消对话框、探针开关默认关闭且两种脚本都能编译；2026-11-11 增加 4 条：
  预览列表、只存勾选的一条、逐条保存不附转录、空选择/越界下标；
  2026-11-11 再加 4 条问答混排：角色顺序、问/答成稿与计划边界、只存提问、
  逐条保存时每条保留自己的角色。
- 真机 s28（2026-11-08）：知识空间问「写一份《发布前检查》文档…实施计划」→
  ChatGPT / Gemini 回答后，网页栏 IPC 分别存出 `ChatGPT-文档.md`（默认，2 份文档 /
  3 条计划，6.9KB）、`ChatGPT-文档-Word.docx`（点名 doc，14.9KB，unzip 验证正文/表格/
  页眉齐全）、`Gemini-文档.md`（换源，1 份文档 / 3 条计划）。
- 真机第一轮暴露两个排版问题并已修复：计划条目被套成 `- - …`、重复轮次的条目列两遍。
- 重启后页面停在首页时再点保存，明确报「这一页还没有可保存的文档」，没有生成空文件。
- 两条测试会话已删（连带清理网页侧），侧栏只剩用户自己的两条。
