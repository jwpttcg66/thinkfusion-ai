# 工程空间：模型直接读证据回答（2026-11-08）

## 1. 裁决

用户原话：「工程模式，不需要优先问网页，读取本地应该是模型所做的」。

这是在改「第一手回答永远来自网页通道」那条硬规则（2026-11-05 裁决）的**适用范围**，
不是推翻它：知识空间（`workspaceMode === 'knowledge'`）一个字节都没变，网页提问、
原话直发、材料不进第一手问题，全部照旧。

工程空间（`workspaceMode === 'engineering'`）改成：**第一手回答由模型读工程证据给出**。

## 2. 为什么必须这样

网页通道读不到本机文件。工程分析里把「读取 /Users/.../x.txt 有多少条记录」原样发给
网页，它们只能回「无法访问本地路径，请上传文件」。真机连着两轮都是这个结果
（s20 第三轮、s21 第一轮），用户看到的就是「读取文件用了网页」。

工程空间的回答本质是「读证据」，而证据只在本机——所以回答只能交给能拿到证据的一方。

## 3. 行为

| 场景 | 谁回答 | 材料 |
| --- | --- | --- |
| 工程空间，有可用本地模型 | 第一个可用的本地模型 | 用户原话 + 工程证据 |
| 工程空间，只有云端模型可用 | 第一个可用云端模型 | 同上 |
| 工程空间，云端主导且云端可用 | 云端模型（归属裁决优先） | 同上 |
| 工程空间，用户点名了成员 | 被点名的那个 | 同上 |
| 工程空间，一个模型都没有 | 退回网页通道 | 原话（并写明网页读不到本地文件） |

补充规则：

- **只问一个模型。** 读证据是确定性任务，同一份证据问两个模型只是把等待时间翻倍，
  还会接着触发汇总与辩论。要第二个意见就点名另一个成员再问一次。
- **问题没有角色开场。** `【用户的问题】` + 证据，两段，用户原话一字不改放在最前面。
  system 只有两条要求：依据证据、写清路径:行号、不足就说「无法确定」。
- **没有可用模型时如实退回网页**，并且先写一条系统消息说明原因（Ollama 没启动 /
  没配 Key），不假装「工程模式」成功。
- **模型报错也不假装答过**：写「本机模型没有给出回答（原因），这一轮改问网页通道」。

## 4. 与执行阶段的关系

归属规则不变：执行模式仍决定**回答之后**的汇总 / 辩题 / 最终意见由哪一类成员做。

工程空间只有一份回答时，`runExecutionStage` 按既有逻辑跳过（没有可汇总的分歧），
所以这一轮就是「模型读证据 → 给回答」，没有多余的汇总调用，也没有辩论。
