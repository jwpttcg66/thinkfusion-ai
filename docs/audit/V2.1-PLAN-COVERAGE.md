# V2.1 任务书逐条对照（审计 + 实现 + 证据）

> 目的：回答一个问题——**任务书里的每一条，到底有没有落地，凭什么说它落地了**。
> 每条给三样东西：实现位置（文件/函数）、可重复执行的测试、真机证据（能复现的场景）。
>
> 基线：分支 `0.1.2`（从 `47e1926 2.1计划` 起）。文档版本 V2.1（2026-11-06）。
> 相关文档：`docs/audit/V2.1-LOCAL-BASELINE-AUDIT.md`（Phase A 基线）、
> `docs/implementation/V2.1_IMPLEMENTATION_REPORT.md`、
> `docs/testing/V2.1_LIVE_ACCEPTANCE_REPORT.md`。

## 0. 与首轮交付的差别（为什么要有这份表）

首轮交付只做到「主干打通」：双入口、识别、执行链路能跑，就报告完成了。逐条对照后发现有 8 项没有真正落地：

| 缺口 | 当时的状况 | 现在的状况 |
| --- | --- | --- |
| K-03 compare | 只有分类标签，输出仍是散文 | 主导人收到「按维度逐项对比」的要求，结论必须分维度 |
| K-04 extract | 只是标签，网页根本没抓 | `fetchPageText()` 真实抓正文，带状态/指纹/时间；抓不到就明说 |
| D-03 方案评审辩论 | 任务链路完全没接辩论 | 计划生成后、审批前开辩，结论挂在计划卡上 |
| Phase E 结构关系 | 只有目录概览 + 关键词 | 符号索引、调用点、模块依赖、变更影响，且**进主导人材料** |
| Phase F 修复任务 | Review 结论不进入下一轮计划 | 评审问题并进下一轮计划请求，并标注为修复任务 |
| Model Router | 没有 | `routeModels()` 在提问前决定参与模型与理由，落会话 |
| S-01～S-04 | 只有零散断言 | 四条独立安全回归，逐条可跑 |
| 计划校验失败的处理 | 占位符导致任务当场死亡 | 失败原因回传给模型，最多两次自修；报错翻成人话 |

## 3. 产品定义逐条

| 产品要求 | 结论 | 证据 |
| --- | --- | --- |
| 两个顶层入口；工程理解/实施是工程空间内部两种任务 | ✅ | `WorkspaceMode` / `TaskRouting`；侧栏两个 tab |
| 知识空间不需要选工程、不启动 Runtime | ✅ | 知识会话不带 `workspaceRoot`，不走 `submitWorkspace` |
| answer / research / compare / extract 四类 | ✅ | 前两类走原链路；compare/extract 有专属写法与真实抓取 |
| 意图优先级：用户明确 > 空间 > 上下文 > 规则 | ✅ | `routeTask({override})` 优先；`source: 'user_selected'` |
| 不确定时询问，不擅自进高权限 | ✅ | `taskKind: 'clarify'` → `awaiting_user`（真机 s7） |
| 默认权限只读（工程分析） | ✅ | 分析链路不产生计划；只读预设只放四个读工具 |
| 识别实施 ≠ 获得权限 | ✅ | 计划必须审批；只读预设下写入计划在 `approve()` 里被拒 |
| 六种辩论策略可复用 | ✅ | 未改 `DebateEngine`；`debateStrategy` 透传（`check-debate-strategies`） |
| Auto 不无声扩大调用/成本 | ✅ | `shouldDebatePlan('auto')` 只在 ≥3 步或含写/测时开辩；`routeModels().estimatedCalls` 明示成本 |
| 用户关闭辩论时不启动 | ✅ | `debateMode: 'off'`；真机 s2 |
| 执行模式 / 协作策略 / 辩论策略正交 | ✅ | 三个独立字段，互不推导 |
| Model Router 选择模型 | ✅ | `routeModels()` + `Conversation.modelRoute` + 界面显示 |
| Evidence 追踪网页/代码/执行 | ✅ | `pageEvidence` / `engineeringEvidence` / `ExecutionReport`（跨会话证据库仍属 P5，未做） |
| 思考与执行严格分离 | ✅ | 模型只出计划；Runtime 只认审批过的计划；无 shell |
| 默认只读、限制在指定目录、写操作需确认 | ✅ | `resolveGrantedPath` + `assertGrant` + 审批 |
| 模型输出不能作为 Shell 指令 | ✅ | 命令白名单 + `shell:false` + 固定 argv |
| 测试结果必须真实 | ✅ | `test.run` 返回真实退出码/输出/耗时；Review 检查「改了文件却没测试」 |
| 不破坏历史会话/任务/辩论 | ✅ | 新字段全可选；`start({text})` 旧调用行为不变（`check-runner.mjs` 首条断言） |

## 4. 边界（明确没做，别误报）

- **跨会话证据库（P5）**：证据只属于本条会话。
- **多轮自主研究（P6）**：一次提问一轮协作，不自动续问。
- **AST / 符号级调用图**：目前是正则 + 静态 import 解析，材料里写明识别方法。
- **全自动修复循环**：评审→修复计划→执行是自动串起来的，但**每轮计划仍要人批准**。
- **方案评审辩论只用本地/云端模型**：网页此刻在当计划生成器，同一条会话里塞辩论请求会把两者搅在一起。
- **真实模型事实准确率**：`DEBATE_ACCEPTANCE.md` 已写明阶段验收 ≠ 准确率结论。

## 5. 复跑方式

```bash
cd desktop-agent-macos
npm run typecheck         # 三套配置
npm test                  # 43 个子脚本 / 620 条用例
npm run build             # electron-vite + agent
```

真机场景脚本与日志在 `/tmp/tf21/`（s1～s14），结果 JSON 在 `/tmp/tf21/results/`，属于验证产物，不进仓库。
