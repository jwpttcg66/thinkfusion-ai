# ADR 0009：网页通道的角色边界

- 状态：Accepted
- 日期：2026-11-18
- 决策者：用户
- 相关：`AGENTS.md` 第 2/6 节、[P1-002](../archive/implementation/audits/P1-002-DOMAIN-RUNTIME-CONTRACT.md)、
  [AGENTS.md](../../AGENTS.md) §2

## 背景

V3 曾把网页通道统一降为「回答者」，理由是网页不能接收 system、不能使用工具、只收原话。
但知识问答与工程任务不同：

- 知识问答需要有人提出下一步该查/该问什么，网页模型可以胜任；
- 工程任务需要读代码、跑测试、看影响面，网页没有这些能力，不能提问/规划。

## 决策

引入参与者角色 `answerer | questioner`：

- **知识学习 / 通用协作**：网页通道可以担任 `questioner`，生成下一轮追问；
- **工程空间**：网页通道只能担任 `answerer`，不得提问、不得规划、不得主导；
- **执行规划**（生成 `desktop-agent` 计划）始终只允许本地/云端 `ContractInput`，
  与工作空间无关；
- 网页 `questioner` 只接收**单条问题 + 数据**（`QuestionerInput`），
  不接收 system、角色设定、阶段指令、格式要求；
- 网页 `questioner` 不调用工具、不审批、不决定停止。

## 后果

正面：

- 知识问答保留网页模型的追问能力；
- 工程任务不会让无工具能力的网页参与规划；
- 规则仍可被测试：按 workspace 检查角色。

负面与风险：

- 网页 `questioner` 仍需要一条系统生成的问题，必须严格限制为「单条问题」，
  不能演化成固定提示词模板；
- 若网页追问质量差，需要回退到规则追问或本地/云模型；
- 工程模式下没有本地/云提问者时，不进行追问轮，而不是让网页顶上。

## 约束

- 网页 `questioner` 的输入只能是 `QuestionerInput`；
- 禁止给网页发 `ContractInput`；
- 工程任务中 `role=questioner` 的网页参与者必须被 Scheduler 拒绝；
- 任何「请按格式/你是…/第一步…」都非法。
