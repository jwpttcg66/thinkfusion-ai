# 网页回答也流式：轮询已渲染文本，不假装 SSE

> 2026-11-10。用户指出：网页也是逐步输出的，凭什么只有本地/云端能流式。
>
> 结论：能，但不是「接流」，是**轮询 DOM 里已经渲染出来的那一段**，算增量、做改写
> 检测。设计如下，实现落在 `shared/partial-stream.ts` + `page-driver.waitForAnswer`
> 的 `onPartial` 回调上。

## 1. 为什么不能照抄 SSE

| 通道 | 输出方式 | 我们能拿到什么 |
| --- | --- | --- |
| 云端 API | SSE，一个 token 一个 chunk | 正文 / 推理 / 用量，精确 |
| 本地 Ollama | NDJSON chunk | 正文 / thinking / 计数 |
| 网页 | **DOM 渲染**，没有事件、没有 socket | 只能每隔一段时间读一次「当前回答长什么样」 |

所以网页的「流式」本质是**采样**：每 `pollMs`（默认约 250–400ms）读一次当前
已渲染的回答文本，和上一版比较，把差异交给界面。

## 2. 增量规则：追加或整段替换

网页会改写自己：Markdown 收尾、代码块合拢、引用 chip 后插、思考面板收起，都会让
新版本不再以旧版本开头。

```
上一版：第一段
新版本：第一段，第二段        → append「，第二段」
新版本：换了个写法             → reset「换了个写法」（整段替换，不拼）
新版本：和上一版一样           → 不发
```

`diffPartial(previous, next)` 只做这一件事；界面收到 `reset` 就把这一路文本整个
换掉，绝不拼成「半截旧 + 半截新」。这条规则在 `shared/partial-stream.ts`，纯函数，
可离线测。

## 3. 只在通过既有判据后才回调

`waitForAnswer` 本来就在每一轮做这些判断，`onPartial` 挂在它们**之后**：

1. 不是我们自己的提问回显（`containsEcho` / `isOwnPromptEcho`）；
2. 不是整段占位（「正在思考中 / User」这类 `looksLikePlaceholder`）；
3. 不是页面外壳（`stripChrome` / `cutSpeakerLabels` 之后的正文）；
4. 转录里确实出现过我们的问题（`transcriptHasPrompt`）。

任何一条不满足，这一轮就不回调。**宁可晚一点显示，也不把侧栏或推荐位当成回答。**

## 4. 与「是否结束」解耦

`onPartial` 只负责显示，不参与「答案是否稳定」的判断。结束仍由原来的规则决定：
停止按钮消失、文本静止足够久、或 `answerLooksComplete`。这样：

- 流式显示不会让「还没写完」被提前判成最终答案；
- 页面的改写也不会让结束判定抖动。

## 5. 工程模式第一轮：先按住工具请求

工程模式的第一轮可能只回一行：

```json
{"tool":"fs.stat","args":{"path":"src/index.ts"}}
```

如果直接流式，用户会先看到一段 JSON，再看到真正的回答。处理：

- 缓冲区出现第一个非空白字符之前，一个字都不发；
- 第一个字符是 `{` → 认定为工具请求，**整轮不流式**，等宿主读完文件后的第二问；
- 第一个字符不是 `{` → 确认是正文，把攒下的整段一次放出，之后正常逐段流式。

`mightBeToolRequest` / `notToolRequest` 在同一个纯函数文件里，有单测。

## 6. 边界

| 情况 | 行为 |
| --- | --- |
| 页面把回答改写成完全不同的文本 | 发 `reset`，界面整段替换 |
| 页面一直没有可读正文（登录页 / 空会话） | 不回调，最终照旧报「没有可读回答」 |
| 网页思考面板（Kimi/Gemini） | **不解析**。它不可靠，且与正文混在一起；网页只流正文 |
| 用户取消 | `waitForAnswer` 抛 `WAIT_CANCELLED`，已发出的增量保留为未完成预览，随消息落盘清掉 |
| 页面渲染很慢 | 最坏情况就是「比原来早不了多少」，不会比整段更差 |

## 7. 验收

| 判据 | 怎么测 |
| --- | --- |
| 追加 / 替换 / 相同三种情况正确 | `test:streaming` 的 `diffPartial` 用例 |
| 工具请求不被当成正文 | `notToolRequest` 用例 + 工程模式真机 |
| 最终文本与非流式一致 | 同一条问题各跑一次，比较落盘消息文本 |
| 不误报侧栏/占位 | 既有 adapter 用例仍全过（回显、外壳、占位） |
| 网页流式不影响首 token 统计 | `trace` 的 `firstTokenAt` 仍取第一次可读正文时间 |
