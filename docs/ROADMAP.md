# 路线

定位见 [PRODUCT.md](PRODUCT.md)，架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

**排序原则：先把「结论可被检验」做通（0.3），再依次补知识学习（0.4）、工程能力（0.5）、
通道与模型（0.6）。** 一个连证据都追不到的结论，接十个模型只是把噪音放大十倍。

每个阶段给的是**完成判据**，不是功能清单。判据不满足，不进入下一阶段。

## 0.3.x 审辩闭环：把证据接到结论上

主题是**可验证**。用户不需要知道内部有几段，只需要能回答「凭什么」。

| 里程碑 | 内容 | 完成判据 |
| --- | --- | --- |
| 0.3.1 裁判可见 | 辩论结论、方向判断（supports / contradicts / context）、置信度与局限进入界面，可按轮次回看 | 界面上每条结论都能展开到「哪条 Claim、哪条证据、哪个裁判判断」 |
| 0.3.2 执行证据接线 | 把已合并的执行证据生产者接入辩论编排器：验证意图 → `test.run` → `ExecutionReport` → attestation → Pack | runtime Claim 的证据必须来自真实执行；没有显式验证意图就不跑测试 |
| 0.3.3 外部事实核验 | 对超出代码与执行范围的 Claim 做来源核验（网页原文、版本、时间） | 无法核验的主张必须标为「未核验」，不能默认成立 |
| 0.3.4 复验与回放 | Pack 可回放：同一 commit、同一证据、同一哈希，重复校验得到同一结论 | 篡改任意 attestation 字段都会被拒绝，且报出是哪个字段 |

判据：**一条结论从「谁说的」到「凭什么」的全路径可以在界面上走完，且第三方能按同样路径复验。**

## 0.4 知识学习：从「一次结论」到「知识资产」

0.3 让一次结论可检验，0.4 让它可积累。知识学习空间的主题是：**第二次研究不应该从零开始。**

- **索引**：Claim / Evidence / 结论按主题、来源、版本（提交或网页快照）、时间落库并可检索；
- **复用**：再次问同一主题时，先带出旧结论，标注依据的版本与时效；被新证据推翻的旧结论保留并标记；
- **缺口驱动研究**：把「没人回答的角度」变成下一轮问题，多轮自主研究直到缺口收敛或预算耗尽；
- **知识地图**：一个主题下分「已确认 / 有争议 / 未回答」三块，每一块都能指向证据与出处。

判据：**同一主题隔一段时间再问，系统能说清「上次结论是什么、依据有没有变、现在还缺什么」；
旧结论被推翻时不会静默消失。**

## 0.5 工程能力：从「读懂」到「可验证的改动」

工程空间在 0.3 已有读盘证据、评审与受控执行；0.5 把它做成一条**可审计的工程链路**：

- **代码智能进第一手材料**：符号、引用、调用链、影响面按需进入汇总材料，结论带 `路径:行号`；
- **改动前后都有证据**：计划阶段给出影响面与测试选择理由；执行阶段产出 `ExecutionReport`
  与 attestation，进入同一套 Pack；
- **评审独立**：评审不跟着实现者走，意见回到计划，不直接改代码；
- **多 Agent 协作**：理解 / 实现 / 评审 / 验证分角色，任务各有 worktree，合并前必须验证；
- **可回退**：快照、diff、回滚是一等能力，而不是操作者的记忆。

判据：**任取一次改动，能回答「改了哪些文件、为什么、影响面多大、哪条测试证明它、失败怎么回退」，
且每个「已通过」都有执行断言。**

## 0.6 通道与模型：扩供给，不降标准

- 本地模型与云端模型并列，路由理由可见；降级必须说出来；
- 外部 CLI Agent 作为通道之一，输出仍按同一套 Claim / Evidence 契约归一；
- 新增通道不改主流程：加一个来源只加一个 Adapter 与一份画像。

判据：**新增一个模型或来源，不需要改辩论、裁判与证据链的任何一行。**

## 1.0 判据

不是功能清单，是 PRODUCT.md 第 8 节那几条全部成立：

- 能指出单一 AI 漏掉的角度，并给出原话与轮次；
- 能指出被反例打掉的说法，而不是悄悄删除；
- 每条结论有证据或被标为断言；
- 一致不被当成正确；
- 「凭什么」有一条可走通的路径；
- 拔掉 Runtime，问答与审辩仍完整；
- 换裁判模型，结论方向不无故翻转；
- 同一主题的第二次结论能复用第一次的证据，并标出时效；
- 工程改动里的每个「已修复」都有执行断言与可回退路径。

## 明确不排期

| 事项 | 原因 |
| --- | --- |
| 多用户 / 云端协作 | 单机产品的结论可信度先做对 |
| 移动端 | 桌面端定位没稳之前不做 |
| 第三方插件市场 | 内部能力插件化已完成，对外安装接口未稳 |
| 「更多模型」竞赛 | 模型数量不是差异化，证据链才是 |
| 通用浏览器 | 内嵌网页只是接入手段 |

## 怎么判断一个阶段真的完成

1. 判据能在**真实模型、真实仓库、真实执行**下跑通，不是脚本桩；
2. 失败路径有明确输出：拒绝、降级、未核验，三者不能混成「成功」；
3. 文档与代码对得上：`docs/spec/` 里的契约改了就同步改；
4. 回归可复跑：同一输入重复执行，结论方向与证据哈希可解释。
