# 辩论质量达标线

对应任务书 §14.3 七项质量指标、§7 裁判与证据评价，以及上一版留下的
「阶段完成不等于质量达标」。本文定义**什么叫达标**、**怎么复算**、以及
**哪些项本仓库算不了、要达标需要什么**。

一键复核：

```bash
cd desktop-agent-macos
npm run quality:debate
```

不过就 `exit 1`，报告写到 `docs/reports/DEBATE_QUALITY.md`；不写 `TF_REPORT=1`
时只落到 `out-test/`，不弄脏仓库。报告含十一项硬门槛逐项的通过数、13 条基准
场景逐条结果、过程指标与无法达标项。

---

## 1. 达标的定义

**达标 ≠ 事实准确率高。** 本仓库没有人工标注集，给一个准确率数字就是编的。
达标定义为两层，都要过：

1. **十一项硬门槛全部通过**（`src/main/debate/quality.ts`）。这些是从落盘数据
   就能算出来的布尔检查，与模型措辞无关，是「结论可信」的底线。
2. **13 条基准场景全部通过**（`scripts/fixtures/debate-labels.mjs`）。标签按
   来源分三类，报告里分开算，不合并成一个准确率。

不达标时报告会列出**具体哪一场、哪一项、什么明细**，不是只给一个分数。

### 十一项硬门槛

| 门槛 | 检查什么 | 依据 |
| --- | --- | --- |
| `verdict.recomputable` | 落盘结论 == 当前规则对同一份发言/证据重算的结果，逐条判定也一致 | §17 结构化校验；规则升级后读老文件会对不上，正是要暴露的 |
| `verdict.no_vote_or_score` | 结论对象里没有 `score` / `confidence` / `supportCount` / `votes` 一类字段 | AC-12 不按多数投票；用户明确要求三维不平均 |
| `verdict.three_dimensions` | 逻辑 / 证据 / 反例三维齐全，各带独立理由 | AC-11 |
| `verdict.evidence_consistent` | 说「有证据支持」，选中主张的证据维度必须是 `sufficient`/`partial`；说「证据不足」，不能在未说明分歧未决的情况下晾着有充分证据的主张；判 `unsupported` 时每条都得不成立 | AC-13 |
| `evidence.no_support_without_link` | 任何 `supported` 主张名下都必须有 `page-link` | §7.2；「页面没给链接」不等于「来源已核验」 |
| `evidence.no_duplicate_independence` | 同一 `originKey` 只允许一条证据被标成独立；独立来源数 == 按地址去重后的来源数 | AC-10 / TF-D-012 |
| `minority.preserved` | 少数派原文在最终记录里逐字存在 | §14.3 分歧保留率 / TF-D-008 |
| `events.idempotent` | 事件 `key` 唯一、`seq` 单调（老文件没有事件流就不判定） | AC-14 |
| `judgments.cover_claims` | 每条主张都有判定，没有孤儿判定 | §17 |
| `judgments.verdict_subset` | 整场合成子集 == 全量判定去掉问句，不丢可判主张 | AC-11 / §7.1 |
| `graph.traceable_edges` | 论证边都带 `roundIndex` 与来源对象（老文件没有图就不判定） | AC-08 |

`supported`，`quality:debate` 立刻变红并列出受影响场景。不是摆设。

`judgments.verdict_subset` 校验「合成只去掉问句、不丢可判主张」。修复后连跑
多场稳定达标。这件事说明达标线必须用真模型输出验过，光靠固定回放不够。

口径上有两处容易写错，已在代码里注明：

- `independent` 是**整场视角**的「谁是第一条」，转载那条也有真实地址。
  判断「有没有链接」不能拿它过滤，否则转载主张会被凭空说成「无来源」。
- `independentSourceCount` 按 `originKey` 去重。TF-D-012 禁止的是「同一份
  材料被算成 2 个独立来源」，不是禁止两条不同主张各引一次同一份文档。

### 13 条基准场景

| 标签来源 | 条数 | 含义 |
| --- | --- | --- |
| `rule` | 11 | 期望值由任务书条款 / AC 直接推出，复核方式是读条款，不是问模型 |
| `seed` | 2 | 本仓库自带的示例标签，**未经人工复核** |
| `human` | 0 | 人逐条标注的，当前一条都没有 |

覆盖 TF-D-001 / 002 / 003 / 006 / 007 / 008 / 009 / 010 / 011 / 013，
外加三条对抗用例（归档材料撑当前版本、空洞推理、规范句里的全称量词）。
每条 `basis` 写明「凭什么期望这个档位」，避免标签变成照抄系统当前输出——
否则实现一改标签跟着改，评测就什么也测不出来。

**回放而不是真跑模型**：同样的问题模型每次说的话都不一样，断言「模型说了
X」的用例第二天就会红，而且红得没有意义。这里守的是链路与判据不回退。

## 2. 任务书 §14.3 七项指标，逐项交代

| 指标 | 状态 | 口径 / 为什么 |
| --- | --- | --- |
| 事实准确率 | **算不了** | 需要人工标注基准集。报告里的「与 `rule` 基准一致 11/11」只能读成「与任务书规则推出的期望一致」，**不是准确率** |
| 证据可追溯率 | 已算，报告值 | 被判定主张中至少有一条 `page-link` 且非同源转载的比例；分母为 0 时给 `null`，不写成 0% |
| 错误前提纠正率 | 已算，报告值 | 带错误前提的用例里发言出现正确说法的比例；与结论档位无关 |
| 无效辩论率 | 已算，报告值 | 除首轮外，既无新证据、也无实质修订、也无新争议的轮次占比 |
| 成本与延迟 | **部分** | 总耗时、每轮耗时、调用次数、失败次数已算；**Token 与费用无数据来源** |
| 校准度 | **算不了（有替代）** | 五档结论不带置信度，给数字就是编的。这里做的是「档位 ↔ 证据强度自洽」的确定性检查，不是概率校准，两者不能互相冒充 |
| 分歧保留率 | 已算 + 硬门槛 | 少数派原文完整保留，设计上应恒为 100%，掉了就是回归 |

过程指标**不设达标线**：可追溯率取决于页面有没有给链接（本地模型永远不给），
无效轮次取决于场景复杂度。给它们编一个「≥ 80%」只会逼系统去凑数字。

## 3. 这一轮修掉的真实质量缺陷

都是从对抗性诊断里复现出来的，先量化误判再改，每条配回归用例：

1. **逻辑假阳性**：规范句「所有 HTTP/1.1 请求都必须带 Host 头」因含「所有」
   被判 `questionable`。绝对化措辞拆成「认识性强断言」与「全称量词」两类，
   规范/定义/义务句里的全称量词豁免；「任何版本都可以」照旧标记。
2. **逻辑假阴性**：`REASONING` 一命中就认为有依据，于是「因为大家都这么说」
   「因为它是可靠的」全判 `valid`。新增诉诸众人与循环论证判据（循环用字符
   级重合，bigram 抓不到同义反复）；真推理链「因为命令执行是单线程的，所以…」
   不误伤。
3. **时效性无判据**（§7.3）：2018 年归档的 v1.0 手册能撑起「7.0 里默认值
   改成 2048」并判 `sufficient`。现在两边都写明版本且对不上、或标题写明归档
   而主张问当前版本时降为 `partial`。**不拿 `fetchedAt` 判过期**——那是抓取
   时间，不是发布时间。
4. **版本判据自引入的假阳性**：第一版把「HTTP/1.1」和「Section 5.4」比对成
   版本冲突。收紧为只认显式版本标记（`v1.0` / `版本 7.0`）与中文版本语境
   （`在 7.0 里` / `6.0 之前`），裸小数不算。
5. **网页引用系统性失效**：`claimsForCitation` 要求锚文字出现在主张里，但网页
   引用常画成上标或 chip，锚文字（「RFC 7230」）几乎不会原文出现在句子里。
   新增**唯一关联**判据：一条发言只切出一句主张、且页面只给一个引用时认领，
   关联是页面气泡给出的，不是猜的；多主张或多链接一律不启用，参考资料列表
   不会被全量认领。认领的证据标 `soleAttribution`，相关性检查不再用字面重合
   二次否决它。`assessment` 如实写明「内容是否支持该句仍需人读」。

判据缺陷回归 8 条（`check-debate-judge.mjs` 现 26 条），加上基准集 13 条和
十一项硬门槛，一起守着。

## 4. 要真正提升「事实准确率」，还缺什么

按优先级，这些不是本轮能靠代码补上的：

1. **人工标注集**：人对每个场景标注正确结论档位与依据（`labelSource: human`），
   并扩充到有统计意义的条数。在此之前任何「准确率」都只是自洽性。
2. **网页正文抓取**：现在只保留回答里的链接与文本线索，判不了 `§7.3` 的
   「引用内容是否确实存在」。要独立立项，不破坏现有提取器。
3. **裁判读得懂证据内容**：规则裁判只能读「文本里写了什么」，判不了
   「这份文档到底写了什么」。这是能力边界，不是阈值没调好。
4. **置信度**：若将来要概率校准度，得先让裁判输出有依据的概率，并且口径
   与本报告里的「档位自洽」明确分开，不能混叫校准。
5. **Token / 费用**：三条通道统一上报用量。

阶段完成不等于质量达标；**门槛全过也不等于结论事实正确**。这句话留在
这里，免得这份报告被读成「系统已经会判断真假」。
